# الرؤية — لماذا نكسوس؟

## المشكلة

تُخفق مشاريع التداول الخوارزمي عادةً بإحدى طريقتين:

1. **تُخفي الحقيقة.** مقاييس مفبركة، إخفاقات صامتة، والفجوة بين الاختبار
   التاريخي والتشغيل الفعلي لا تُقاس أبداً.
2. **تسرّب المستقبل.** الخصائص أو الملصقات تستخدم معلومات لم تكن متاحة لحظة
   القرار — نتائج غير صالحة بنيوياً مهما بدت جيدة.

بُني محرك نكسوس ضد كلا الفشلين: **خط أنابيب كامل قابل التدقيق** — بيانات
السوق ← الخصائص ← النموذج ← السياسة ← المخاطر ← التنفيذ ← المحاسبة ←
البحث — حيث كل مرحلة قابلة للرصد، وكل هوية مُسجَّمة ببصمة، وكل ادعاء قابل
للدحض.

## الفلسفة (مدعومة بالمستودع)

- **الأدلة قبل الادعاءات.** المقاييس بلا أدلة تُعرض `n/a` — أبداً أصفاراً
  مفبركة.
- **لا إطلالة للمستقبل.** walk-forward مع purge و embargo، خصائص سببية صارمة
  (INV-008).
- **التكافؤ السببي.** live = replay = التدريب؛ عقد الخصائص نفسه مع بصمة
  المخطط.
- **حقيقة وقت التشغيل.** حقيقة الوسيط تغلب الحالة المحلية القديمة (INV-011)؛
  صفوف السجل التاريخية غير قابلة للتغيير (INV-007).
- **بنية طبقية.** ports-and-adapters؛ مكوّنات البحث/التعلم بلا سلطة أوامر
  (INV-002).
- **التحقق قبل الترقية.** فشل OOS ⇒ REJECTED؛ الترقية بقرار المشغّل حصراً.

## الحالة الصادقة

NSE **وقت تشغيل مُتين بموقف بحثي صادق**: خط أنابيب الإصدارات منشور فعلياً
(وسوم v9.0.x)، والتنفيذ الحي على MT5 يعمل مع fail-safe مطابقة الحساب، وحلقة
البحث المغلقة قائمة — بينما تظل سلسلة 70D **مرشّحاً فقط بأدلة OOS سلبية
حتى الآن**، والعقد الحي يبقى 50D عمداً. لا شيء يُرقّى تلقائياً.

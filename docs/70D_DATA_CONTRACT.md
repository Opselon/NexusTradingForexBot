## 1. Canonical vector layout (INVARIANT)

```text
index  0..49   Base 50D     = scalp_v1 protected contract (UNCHANGED)
index 50..59   News 10D     = news_context_v1 fields 0..8 + news_state (index 10)
index 60..69   Liquidity 10D = liquidity_engine.compute_liquidity_features as_vector() order
```

The vector is ALWAYS generated by index from the canonical name tuple.
Never `list(features.values())` — the registry controls ordering.

### 1.1 News 10D selection (documented decision)

The repo's canonical news context is the 12-field `news_context_v1`
(`model_generation/news_bridge.py`). The 70D news block keeps:

```text
0 active_high_impact_events   5 conflict_score
1 xauusd_relevance            6 novelty
2 usd_relevance               7 freshness
3 bullish_pressure            8 confidence
4 bearish_pressure            9 news_state (index 10 of the 12-field vector)
```

`source_consensus` (index 9 of the 12-field vector) and
`time_since_event_sec` (index 11) stay OUTSIDE the 70D block by contract
(they remain part of the 12-field context for the 60D path). The selection is
NOT a blind first-10 slice; it is hashed so any drift is detected.

### 1.2 Liquidity 10D (canonical order)

```text
60 bsl_distance_atr           65 internal_liquidity_distance
61 ssl_distance_atr           66 external_liquidity_distance
62 eqh_strength               67 liquidity_confluence
63 eql_strength               68 liquidity_sweep_state
64 htf_liquidity_score        69 post_sweep_displacement
```

Producer: `features/liquidity_engine.compute_liquidity_features` →
`LiquidityFeatures.as_vector()`. Causally confirmed pools only; HTF buckets
fully closed at decision time only.

## 2. Schema identity & hash

`feature_schema_hash()` = SHA-256 (first 16 hex chars) of the canonical
registry JSON:

```json
{
  "schema_id": "scalp_v3",
  "schema_version": "1.0.0",
  "dimension": 70,
  "base":      {"count": 50, "end": 50, "start": 0},
  "news":      {"count": 10, "end": 60, "start": 50},
  "liquidity": {"count": 10, "end": 70, "start": 60},
  "features":  [{"index": 0, "name": "...", "family": "base"}, ... 70 entries]
}
```

- The hash covers index, name AND family for every dimension.
- Two schemas with the same dimension but different ordering → different hash.
- Training, replay, inference and live compare the SAME canonical value.
- Current value (2026-08-19): `235b8fccc96b7e0e`

## 4. Family states (never silently guessed)

| State | Meaning |
| :--- | :--- |
| FEATURE_AVAILABLE | family computed from real data |
| FEATURE_DISABLED | family explicitly off (neutral block, e.g. news off → 10 zeros) |
| FEATURE_UNAVAILABLE | family declared on but no data → SNAPSHOT/BLOCK (never fake) |
| FEATURE_INVALID | data present but violates contract → BLOCK |

Missing values follow the documented conventions (NaN/Inf → 0.0 then clip
[-3,+3]; liquidity "far" → 3.0; no pool → documented neutral). NEVER a
random sentinel.

## 6. Replay (`replay_70d_vector`)

Rebuilds the canonical vector at a historical timestamp from raw bars +

## 7. Inference validation (`InferenceValidator`)

Full chain before any model call:

```text
EXPECTED_SCHEMA -> ACTUAL_SCHEMA -> DIMENSION -> ORDER -> HASH
-> FINITE -> BOUNDS -> NEWS/LIQUIDITY -> FRESHNESS -> SCALER -> INFERENCE
```

Explicit rejection codes (brief 29):

```text
SCHEMA_MISMATCH / DIMENSION_MISMATCH / FEATURE_ORDER_MISMATCH /
SCHEMA_HASH_MISMATCH / SCALER_MISMATCH / NONFINITE_FEATURE /
OUT_OF_RANGE_FEATURE / NEWS_UNAVAILABLE / LIQUIDITY_UNAVAILABLE /
STALE_FEATURES
```

NEVER silently repairs, pads, truncates or substitutes. Schema metadata
cached at construction; no DB / file I/O on the per-tick path (INV-001).

## 9. Runtime hook (`Runtime70Hook`)

- Observability-only: never touches orders/SL/TP/RiskEngine/execution.
- Thread-safe toggles (news/liquidity) — toggle never corrupts the vector;
  dimension stays 70; family status reflects the toggle.
- `[FEATURE_CONTRACT]` structured trace: VALID (schema/dimension/hash/news/
  liquidity/status) or REJECTED (reason, expected/actual, correlation_id).
- Per-stage timing: base/news/liquidity/assembly/validation ms.
- Model gate: 70D model + liquidity disabled → MODEL_INPUT_UNAVAILABLE
  (no inference for that snapshot), never fake values.

  the engine actually uses (no frontend-only state).

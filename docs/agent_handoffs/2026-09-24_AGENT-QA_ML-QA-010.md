### Why it flakes

Every BUG-262 scenario asserts a *relationship* against the detection instant
("evidenced close is 2 h before detection", "+3 h server-local stamp refused",
"fallback = detection ± 5 s"). Reading `datetime.now(UTC)` for that instant
made each relationship host-clock-dependent in two ways:

- **date boundary** — a run starting 23:59:59 UTC computes `now - 2h` in
  *yesterday*, moving a close into a different accounting day/week bucket;
- **tolerance widening** — the `< now + 5 s` windows are real durations, but
  their endpoints moved with the wall clock, so a co-tenant-scheduled pause
  between the `now` read and the assertion shifted the window off the evidence.

### Fix (tests/ only)

- **Injected fixed clock.** `_FIXED_NOW = datetime(2026,9,24,14,37,12, tzinfo=UTC)`
  via `_now()`, replacing all 11 `now = datetime.now(UTC)` reads. Positioned
  mid-day / mid-minute / off the zero second so a future regression fails in
  both bucket directions.
- **Injection at the real seam.** `reconcile_missed_closes` derives detection
  from `current_tick.timestamp` (`execution/lifecycle/reconciliation.py:106`),
  so `_tick_ts(bid, ts=None)` injects there; the classic `_tick(bid)` signature
  is preserved as a wrapper. `ts` keeps the pre-gap tick shape.
- **Repair path.** `OutcomeRepairJob` owns 4 `datetime.now(UTC)` sites through a
  module-form import, so the `datetime` *name* is patchable: a minimal
  `_FrozenClock` (`now()` + `UTC` + fall-through) installed by
  `monkeypatch.setattr`, auto-reverted per test.
- **`mkdtemp()` → `tmp_path`** (4 sites); dead `os` import removed.
- **No assert weakened.** All relationship asserts preserved byte-for-byte; the
  5 s tolerances stay real `timedelta` arithmetic around the injected instant.
- **2 new invariant tests**, including the exact-equality assert the wall clock
  had forced down to `close < now + 5 s`.

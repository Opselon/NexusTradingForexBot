## 1. Objective

A failed conflict resolution must not be able to reach `git` — especially the
partial-marker shape where only the leading `<<<<<<<` line is stripped and the
diff3 middle arm is committed as literal content.

This is not a hypothetical. It happened on `main`: PR #347 (merge `159cd3b3`)
shipped the `||||||| eb73440a` arm into two single-source-of-truth metadata
files, together with a duplicate contradictory task row. It survived every
gate because the only existing detection (`grep -n '<<<<<<<'`) looks for the
one line that *was* stripped.

## 2. Evidence found at HEAD (root cause, reproduced)

Four tracked files lines carried diff3 residue on `main` (git blame: PR #347):

| file | line | content |
|---|---|---|
| `docs/ml-system/06_TASK_LEDGER.md` | 83 | `\|\|\|\|\|\|\| eb73440a` |
| `agents/taskboard.md` | 328 | `\|\|\|\|\|\|\| eb73440a` |
| `agents/taskboard.md` | 391 | `\|\|\|\|\|\|\| ec6ad155` |
| `agents/taskboard.md` | 441 | `\|\|\|\|\|\|\| c2a0af3d` |

Both ledger rows the marker bracketed were kept, so `06_TASK_LEDGER.md` had
**three** `ML-CI-002` rows: one `DONE (PR #346)`, one `**BLOCKED**`, and one
`DONE` owned by `AGENT-GIT`. The owner attribution was also wrong — the task
file's own `AGENT_ROLE:` line says `AGENT-QA`, and `AGENT-GIT` was the
implementer of one sibling lane, not the ledger's canonical owner.

`agents/taskboard.md` had two `ML-CI-002` rows (a byte-differing duplicate of
the same summary text).

No CI or local gate detected this. Verified by grep across `scripts/ci/`,
`scripts/docs/` and `tests/`:

- no gate scans for diff3 markers,
- `check_ml_contract_drift.py` (ML-CI-002) checks values, not marker syntax,
- `check_docs.py` verified 27,484 links and reported `DOCS_HEALTH = PASS`
  while the ledger table was malformed.

## 3. Delivered

### 3.1 `scripts/ci/check_merge_marker_residue.py` (new gate, stdlib-only)

Scans every file in `git ls-files` (not a fixed directory — the leak class can
land anywhere) and fails on any line starting with one of the three
unambiguous diff3/merge2 markers:

- `<<<<<<<` (conflict open)
- `|||||||` (diff3 original separator — the arm PR #347 leaked)
- `>>>>>>>` (conflict close)

`=======` is deliberately **not** matched. It is ambiguous with a legitimate
RST underline / setext heading, and this repo ships exactly that shape in
`src/nexus_scalp/model_lifecycle/champion_sentinel.py:5` and
`src/nexus_scalp/research/trading_metrics.py:6` (verified: those lines are
docstring section underlines, not residue). Any real conflict block still
containing `=======` also contains `<<<<<<<` and `>>>>>>>`, which the gate
flags anyway — so dropping the bare separator costs no coverage while removing
a false-positive class.

Binary files (NUL byte or high control-byte ratio) and >8 MB files are
skipped with counters, not errors. Fail-closed: exit `0` clean, `1` residue,
`2` tooling error (e.g. missing root). `--json` emits unwrapped stdout
(`json.dumps` to `sys.stdout.write`, never a rich console — the BUG-300
console-wrapping lesson).

### 3.4 `tests/unit/test_merge_marker_residue.py` (new, 20 tests, critical-suite registered)

Five test groups:

1. **committed tree is clean** — `check_residue(REPO_ROOT)` is `ok`,
   CLI exit 0, `--json` parses with `findings == []` and >1000 files scanned;
2. **the PR #347 incident class** — the exact `||||||| <sha>` arm shape is
   flagged at the right line with the sha in the detail; every marker family
   is parametrised; a full conflict block is caught;
3. **no false positives** — a lone `=======` RST underline is clean, prose
   mentioning `<<<<<<<` is clean, a binary file is skipped without a tooling
   error, and untracked working-tree residue is ignored (the gate is a
   committed-tree contract);
4. **engineering properties** — <30 s budget, deterministic across runs,
   no `torch`/`polars`/`pydantic` import in the gate, CLI fail-closed (`1`),
   missing root `-> 2`;
5. **regression pins** — the two incident files are marker-free at HEAD and
   each carries exactly one `ML-CI-002` row.

## 6. Design decisions & honest limits

- **`=======` is not matched.** Trading a small coverage gap for removing a
  real false-positive class (RST underlines). Documented in the gate's own
  docstring so the next agent does not "fix" it back.
- **Prose containing a marker is not flagged** — only a line *starting* with
  one. This makes the gate precise but means a marker inside a fenced code
  block would also trip it; that is the correct fail-closed bias for a CI
  gate, and the exemption list is empty today.
- **Untracked residue is ignored.** The gate is a committed-tree contract; a
  working tree mid-conflict-resolution must not fail it.
- **`grep -n '<<<<<<<'` alone is not sufficient** — the incident's marker
  line was the *only* one stripped. Detecting all three marker families is
  what makes the guard match the actual leak shape.
- **The docs gate's blind spot is recorded, not silently fixed.**
  `check_docs.py` returned PASS over a malformed table; table-shape integrity
  of `agents/taskboard.md` / `06_TASK_LEDGER.md` is now covered by the
  marker/duplicate-row regression pins in §3.4 group 5, but a general
  markdown table validator is out of scope here.

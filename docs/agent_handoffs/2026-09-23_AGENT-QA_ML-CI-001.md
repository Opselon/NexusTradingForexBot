# 2026-09-23 — AGENT-QA handoff: ML-CI-001

## Task
**ML-CI-001 — CI Model Training Smoke vs Real Validation Gap & Nightly Harness**
Stream L (Observability, Safety & CI/CD), P2, AGENT-QA. Status: **DONE (PR pending)**.

## Problem
PR checks deliberately cap training at a fast synthetic smoke drill
(`SMOKE_MIN_ROWS=3000`, fractions of the pipeline) so CI stays under its
timeout. The consequence: the *real* training path — fold construction,
purge/embargo geometry, atomic candidate-bundle publication, the hard emission
gate, producer→gate evidence wiring — is never exercised in CI. A regression
inside any of those can land on `main` and only surface at the next real
candidate run, when it costs a full training cycle to find.

## Deliverables

### 1. `tests/integration/test_walk_forward_pipeline_real.py` (new, 11 tests)

Drives the real `WalkForwardTrainer.train_and_validate` path end to end —
5 folds × 3 epochs on a 720-row synthetic 50D frame, real purge + embargo
splits, atomic candidate-bundle publication — not a stubbed or
short-circuited drill. A module-scoped fixture trains once and every test
inspects the same run (its metadata, fold geometry and published bundle).

The frame is a threshold rule on the first feature plus 10% label noise, so
the model has genuine signal to learn; the battery must prove a REAL run
completed (non-trivial OOS accuracy, real economics), not that a degenerate
all-`NO_TRADE` fold looped five times. `label_origin` is stamped
`CLEAN_HISTORICAL` so the MLFIX-T7 lineage guard admits the run.

Assertions, each an honest property of a completed run:

| Test | Property |
|---|---|
| `test_walk_forward_completes_within_budget` | AC-1: 5-fold × 3-epoch finishes < 180 s on CPU |
| `test_run_used_the_requested_folds_and_epochs` | the run really was 5 folds × 3 epochs; trainer metadata agrees with the artifact manifest |
| `test_fold_geometry_is_a_real_walk_forward` | every fold has non-empty train + validation blocks, the exact 15-bar purge band strictly between them, time-ordered validation indices — the leakage contract |
| `test_pooled_oos_scored_on_a_real_validation_block` | pooled OOS samples == Σ fold validation-block sizes; accuracy beats the 1/3 majority share |
| `test_published_bundle_is_complete_on_disk` | `model.pt` + `model.scaler.npz` + `model.meta.json` + `manifest.json` present, no `.staging-*` leftovers |
| `test_manifest_hashes_match_the_bytes_on_disk` | the manifest's recorded model/metadata/scaler SHA-256 match a fresh hash of the bytes on disk (load integrity, not a filename check) |
| `test_emission_gate_admitted_the_published_tensors` | head really is 3-wide (`classifier.weight`), input projection 50-wide — the live loader resolves the head from the checkpoint, not the meta |
| `test_production_eligible_gate_rejects_the_smoke_bundle` | `smoke=true` / `production_eligible=false` and the eligibility gate FAILS — a nightly benchmark bundle can never promote |
| `test_gate_evidence_is_real_not_not_available` | GATE4/GATE5/GATE11 pass against the real artifact; the honest `NOT_AVAILABLE` sentinel would fail loudly here |
| `test_economics_are_reported_per_fold` | every fold carries net/gross expectancy in R, win rate, trades; aggregates derived, never fabricated |
| `test_nightly_harness_is_deterministic_at_the_pinned_seed` | a pinned-seed rerun reproduces identical fold geometry AND identical model SHA-256 (skippable via `NSE_NIGHTLY_SKIP_RERUN` on a loaded runner) |

**GATE11 wiring note (found while writing this test).** `gate_artifact_integrity`
accepts either a dict or a `ModelArtifactInfo`. Its dict path reads
`integrity_ok` / `feature_dimension` / `num_classes`, but the bundle
`manifest.json` the trainer publishes has **no `num_classes` key** — so
passing the raw manifest returns `dim=70 classes=None` and FAILS on a
perfectly valid artifact. The promotion pipeline never hits this because it
passes the producer's `ModelArtifactInfo` object. The test therefore goes
through `model_lifecycle.integrity.inspect_artifact()` — the same inspector
promotion uses — which derives the width and head count from the serialized
tensors and hashes the bytes on disk, then hands the resulting
`ModelArtifactInfo` to the gate. That is the honest path; a manifest-field
check would be testing a mapping, not an artifact.

### 2. `.github/workflows/nightly-ml-benchmark.yml` (new)

`cron: "41 2 * * *"` + `workflow_dispatch`, 30-minute timeout, one job:
checkout → Python 3.11 (pinned action SHAs matching the repo set) →
`pip install -e ".[dev,web]"` → run the battery **serially** (`-p
no:cacheprovider`, no `-n auto`) — the xdist worker pool has died under
memory pressure on this repo's CPU-heavy training batteries on the
3.9 GB / 2-core host.

per-run `ml-benchmark-results/` tree, a Python step parses the junit XML for
test/failure counts and wall time into `report/metrics.json` (verified
locally: `{"tests": 11, "failures": 0, "seconds": 4.245}`), a
`$GITHUB_STEP_SUMMARY` block renders it, the `nightly-ml-benchmark-<run>`
artifact uploads with 30-day retention, and failure notifies Telegram through
the canonical `scripts/ci/telegram_notify.py release-failed` (signature
verified: `--tag --failed-phase --error-class --error-detail`).

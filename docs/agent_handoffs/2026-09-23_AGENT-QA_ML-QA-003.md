## 3. Census method

A stdlib-only scanner (`re` + `pathlib`, no torch/polars/repo import, so it
runs in the slim Linux venv) walks `tests/**/*.py`, matches the canonical
non-determinism source patterns, records each shape's hit count and first
`file:line` occurrence per file, and cross-references the path against
`tests/critical_suite.txt`. The critical suite is a *path manifest* (233
entries), so an entry covers the whole module.

A file with a seed anchor (`random.seed(`, `SEED`, `fake_`, `freeze_time`,
`torch.manual_seed`, `np.random.seed`, `monkeypatch.*now`) is marked SEEDED
— the author already pinned the randomness, so the remaining sources are
timing/thread, not sampling.

**Synchronization primitives are NOT nondeterminism sources.** `set()`,
`threading.Event`, `Event.set()`, `cancel.set()`, `release.set()` are the
*deterministic synchronizers* a threaded test uses to be reproducible. The
scanner matches the `set(...)`-call shape because a genuine race source
looks identical at the AST surface, so the `dict_order_set` column is an
**upper bound, not a defect count**. Example of a correct hit to discount:
`tests/unit/test_training_env_worker.py:189 cancel.set()`.

## 6. PR #381 drift-gate fix (this cycle, AGENT-GOVERNANCE lane)

PR #381 (BUG-308C, run 34) had one red gate: `Dependency drift (lock vs
pyproject)` — `DEPENDENCY DRIFT DETECTED: requirements.lock is STALE vs
pyproject.toml`.

Root cause: an **upstream patch release** (`cuda-bindings` 13.4.2 → 13.4.3)
landed after the branch's base. The PR's own commits never touched the lock
(`git show 574aee78 --stat` = 7 files, no lock) — the branch was simply 10
commits behind a main that had absorbed the regen. Reproduced locally in
the PR worktree (`DEPENDENCY DRIFT DETECTED`, then OK after regen).

Fix: `python scripts/ci/check_dependency_drift.py --regen` on the PR branch
(local `uv 0.12.10` = the CI pin; the script passes `--python-version 3.11`
and `--all-extras --universal --generate-hashes`, matching CI byte-for-byte).
Result: **only `cuda-bindings` changed**, `requirements.txt` unchanged, 99
pins, `requirements.lock matches pyproject.toml resolution` OK.

Committed `05552d8b` and pushed to `agent/governance/bug-308c`. This is the
documented "upstream dependency release" false-positive-of-sorts: the
branch did nothing wrong, but a PR head must carry a fresh lock to pass the
gate, so the regen belongs on the PR branch.

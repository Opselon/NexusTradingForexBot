## Summary

Main itself was red at 9279f1ea — `CI` (Code Quality & Tests) and `Tests (OS
Matrix)` both failed with `pytest=failed` while every other gate was green
(`ruff_lint=passed | ruff_format=passed | mypy=passed | smoke=passed |
coverage=passed | critical_coverage=passed | runtime_gate=passed |
layered_smoke=passed`). A red main blocks every PR's CI, so this was the
cycle's P0.

Run 28 had recorded this as BUG-307B and attributed it to `configure_logging`
re-creating the structlog global logger class after a manifest reorder. **That
diagnosis was wrong.** The real cause is a process-global `logging.disable()`
leak in a CLI module.

## Root cause (proven by execution)

`src/nexus_scalp/cli/db_commands.py:74`, `_emit(json_mode=True)`:

```python
_logging.disable(_logging.CRITICAL)   # PROCESS-GLOBAL, never restored
print(json.dumps(payload, ...))
```

`logging.disable` mutates `logging.root.manager.disable` — a process-global
threshold. One `db-portability ... --json` invocation permanently silenced
every logger in the interpreter.

CI runs `pytest -n auto --dist loadgroup` on 2-core runners. `loadgroup`
(`xdist/scheduler/loadgroup.py::_split_scope`) groups by the `xdist_group`
mark; **no test in this repo carries one**, so an entire test MODULE is one
scheduling scope. The leak therefore crossed test boundaries inside one
worker:

- `tests/unit/test_cli_end_to_end.py::test_e2e_5*_db_portability_*__json` → `_emit(json_mode=True)` → logging disabled forever
- same worker, later: `test_mt5_diag_throttle.py::test_distinct_error_codes_not_cross_suppressed` → capture fixture sees ZERO records → `assert 0 == 2  +  where 0 = len([])`
- same worker, later: `test_update_cli_contract.py::test_update_lifecycle_logging_reaches_severity_tree` → severity log files empty → `assert '[UPDATE] event=STAGE' in ''`

Both failures share one `[gw1]` header in the `ci-results-quality` artifact.
A PR-head run failed on one testcase of a different module
(`test_replay_toggle_requires_auth`, 200 != 401, `[gw3]`) — same class,
different co-schedule.

## Fix (two layers)

1. **The leak** — `src/nexus_scalp/cli/db_commands.py`: save
   `logging.root.manager.disable`, restore it in a `finally` around the
   `print(json.dumps(...))`. `--json` stdout stays pure: the disable window
   covers exactly that print.
2. **Defense in depth** — `src/nexus_scalp/observability/logging.py`:
   `configure_logging` previously preserved only `LogCaptureHandler` /
   `_LiveLoggingNullHandler` by class NAME and cleared everything else off
   root. It now marks its own handlers with a sentinel and keeps every foreign
   handler, so a co-scheduled test's root capture handler is never evicted.

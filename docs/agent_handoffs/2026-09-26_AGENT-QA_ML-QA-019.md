## 2. The defects

**(a) A push-gate module exercising nothing.** Both durable tests were
guarded by `skipif(not Path("data/raw/XAUUSD_M5.parquet").exists())` on a
data file git never carries (download-only). Both were therefore silently
**UNCOLLECTED** in CI. The module is registered in `tests/critical_suite.txt`
— the push gate — so the gate reported a green module that exercised
**nothing**. The BUG-106 canonical-vs-incremental byte-identity contract had
**zero live coverage anywhere in the push gate** (`tests/slow/` is
out-of-gate and carries the same skipif). pytest rc=5 would have been
honest; the skipif made the suite read green at zero coverage.

**(b) A wall-clock benchmark.** The speedup test read `time.perf_counter()`
on both legs — the same defect class remediated across
ML-QA-007/008/009/011/012/014/018: on a 2-core shared CI runner the wall
clock measures co-tenant scheduler load, not the code under test.

## 3. Remediation (test-only — zero production files changed)

- The real-data dependency is replaced by the deterministic synthetic bar
  generator the gate already uses:
  `scripts.data.ingest_historical_candles.generate_synthetic_bars` — the
  same importer and seed pattern as `test_position_replay_pipeline.py`
  (in-gate). Output is tz-aware UTC M1 OHLCV, exactly the canonical
  broker-fetch shape `compute_70d_frame` consumes.
- The speedup leg measures **CPU time** through the shared `budget_cpu_ms`
  stopwatch from `tests/e2e/chain_clock.py`.
- A new precondition test pins the synthetic frame's schema / sort / tz /
  bar count past the 54-bar warm-up.
- Both builders are now imported at module scope (they were function-local
  *inside* the skipif bodies — the shape that hid the uncollected module).

## 5. CI-only defects caught by the first run (fixed in `b66e2931`)

The first CI run of the PR (`Code Quality & Tests` red, `PYTEST_RC: 1`)
surfaced three defects invisible locally — the exact failure shape this gate
exists to catch. Read from the `ci-results-*` artifact (`pytest/pytest.txt`,
the `short test summary info` block); `gh run view --log-failed` showed only
the aggregate `CHECK pytest rc=1`.

1. **The two subprocess legs hardcoded `/tmp/nse-venv/bin/python`** — the
   operator's local torch venv. CI has no such path, so both raised
   `FileNotFoundError`. Now `sys.executable`, with the site-packages shim
   kept only when it exists on the host. **Lesson: a hardcoded local
   interpreter path is green locally and red in CI by construction.**
2. **The CPU budget was calibrated against the local host only.** The CI
   runner measured **30886 ms CPU** for both legs on 600 bars vs **4255 ms**
   locally — a ~7x CPU-class difference under xdist load. Budget raised to
   60 s (~2x the CI cost): loose to runner speed, tight to a complexity
   blow-up. **Lesson: a CPU budget calibrated on one host is a wall-clock
   gate in disguise — calibrate against the SLOWEST host that runs it.**
3. The behavioural budget leg now reads the declared `_CANON_CPU_BUDGET_MS`
   from the analysed module (lazy textual resolution, the ML-QA-018 pattern)
   so the constant and the speedup test cannot drift apart.

## 6. Battery-authoring defects caught pre-commit

1. **The imported `_code_lines` extractor had a second-order assert-killer.**
   A token's span covers only itself, so a row collecting a code-class token
   (the leading NAME `assert`) AND non-code-class tokens for the rest of the
   *same* row (the OP/NAME/NUMBER after it) cancelled out under
   `code_rows - non_code`. Every `assert diffs == 0` / `assert len(...) == 70`
   line was silently dropped. Fixed to `code_rows | non_code` (a row is code
   when it carries any non-trivia token). The 018 battery's analysed modules
   survived only by accident (single-NAME asserts / `.to_list()` shapes).
   **This is a latent defect in every battery that imports that extractor —
   worth back-patching 014/016/017/018 if they ever assert over a line whose
   tokens split that way.**
2. `pytest -q` under pytest 9.1.1 **suppresses the pass-count line** from a
   captured subprocess report, which would have made the "3 passed" assert a
   tautology — `-v` is used instead.
3. `git diff --name-only origin/main..HEAD` is **empty** on a worktree branch
   that sits at origin/main's own sha (the worktree was created from it, so
   the edits are unstaged relative to HEAD); the no-production-file rule now
   reads the working-tree diff.
4. A bare `'compute_70d_frame'` substring matched `compute_70d_frame_fast`
   too, so the module-scope-import rule passed on the reverted text — pinned
   to the actual `from ... import` lines instead.

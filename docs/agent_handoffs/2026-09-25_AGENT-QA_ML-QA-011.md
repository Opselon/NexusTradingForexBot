## 1. The defect

`tests/unit/test_shadow70_safety.py` carries the TEST-SHADOW-36..40
champion-protection and 70D-shadow safety contracts and is registered in the
push-gate manifest. The recount at `03d2fede` counted 8 live nondeterminism
sources in it: **6 `datetime.now(UTC)`** arguments to
`Shadow70Runtime.observe()`, **1 `tempfile.mkdtemp()`**, and **1 real worker
thread**.

The timestamp is an **input** the caller supplies, never a magnitude a test
measures — so the wall clock carried no information. But it broke two real
properties:

- **Read drift → unprovable idempotency.** Spec 13 derives
  `observation_id = sha256(snapshot_id|model_id|model_version|ts)`. Six
  independent clock reads meant an observation and its retry derived
  *different* ids whenever the reads straddled a tick, so the spec 13/14
  `INSERT OR IGNORE` idempotency contract was **unprovable** — a retry could
  land a duplicate row purely because of scheduler timing.
- **Date boundary.** A scenario reading `now` at 23:59:59 UTC and asserting
  on a derived timestamp crossed a day/week boundary whenever the runner
  stalled, with zero change in the code under test.

The `mkdtemp` scratch dir also leaked on early assert (the fixture generator
aborts before its `shutil.rmtree`).

## 2. The remediation (test-only, zero production code)

- The 6 per-call `datetime.now(UTC)` stamps read **one** module-level frozen
  instant — `_FIXED_NOW = datetime.now(UTC)` captured at import — through
  `_now()`. All observations in a scenario now share one instant, which is
  what spec 13's deterministic identity assumes.
- The instant is **captured, not hardcoded**: the runtime freshness gate
  (`_validate_vector`, `runtime.py`) still compares the supplied timestamp
  against the real clock with a 300 s budget, so a hardcoded calendar date
  would silently flip every scenario to `SHADOW_STALE_FEATURES`. One captured
  read has neither that defect nor the flake class.
- `tmp_artifacts` → pytest `tmp_path`.
- The TEST-SHADOW-40 persistence wait gained a `budget_cpu_ms(4000.0)`
  CPU-time bound (the shared helper ML-QA-004/007/008/009/010 use); the hard
  `n == 60` row-count contract is untouched and the real worker thread stays
  (it is the thing under test).
- **No safety assert weakened** — all five TEST-SHADOW-36..40 tests keep
  their names and load-bearing asserts byte-identical.

Two new proofs became possible *only* under the fixed clock:

- TEST-SHADOW-37: a replay derives the **same** `observation_id` as the
  original — spec 13 idempotency, previously unprovable.
- TEST-SHADOW-40b: persisted rows carry the fixed instant and a retry cannot
  duplicate a row (3 rows survive, `INSERT OR IGNORE`).

## 5. Two battery-authoring traps worth recording

Both cost real debugging time and neither is obvious from the passing state:

- **`Path(__file__).resolve()` and `inspect.getfile(module)` both resolve to
  the shared tree from a worktree.** This repo has the shared checkout at
  `/tmp/NexusTradingForexBot` and the worktree at `/tmp/wt-qa-shadow70`
  simultaneously; `resolve()` follows the worktree's symlinks back to the
  shared tree, and pytest's rootdir-relative import mode canonicalises
  `__file__` the same way. Every textual rule then read the *un-patched*
  original and failed while the module under test was correct. The only
  anchor that survives is the battery file's **own directory**, un-resolved:
  `Path(__file__).parent / "test_shadow70_safety.py"`. ML-QA-010's battery
  carries the same latent shape (`_FIXTURE_SRC` via `inspect.getfile`) and is
  merely saved by never reading the alias.
- **Do not import `re` in a text-analytic battery.** A `re` module or
  package ahead of the stdlib on `sys.path` silently shadows the stdlib `re`
  and can drop a negative lookahead — the pattern then stops matching
  `datetime.now(` *with* the lookahead and matches only *without* it, so the
  rule silently inverts. The battery now uses a lookahead-free
  `str.find`-based call scanner (`_call_spans`), which also removes a
  dependency for the slim venv.

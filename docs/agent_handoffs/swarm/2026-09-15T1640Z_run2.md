## Root cause (file:line at bae2dc19)
- `LiveEngine._session_spread_percentile_provider` opened `self.audit._connect_sqlite(5.0)`
  **on every call** and ran `session_spread_percentile` (SELECT + Python sort).
- `SignalPolicy` invokes that provider from inside `evaluate_probabilities`, i.e. the
  loop thread, whenever `current_spread > 0` and the gate is enabled — so connection
  churn plus a scan whose cost grows with the day's fill count sat on the tick path.
- The provider contract itself was fine (read-only, honest-None); the defect was the
  **placement** of the I/O, exactly as the audit said.

## Fix
1. **New seam** `src/nexus_scalp/experience/spread_sketch.py::SpreadSessionSketch`
   — bounded in-process session distribution.
   - Read surface `percentile(symbol, now_utc, pct)`: pure RAM — no connection, no
     lock, atomic reference swap (a concurrent refresh can never hand the tick path a
     half-built list).
   - Mutation surface `refresh(conn)`: the module's **only** I/O. Cold pass reads the
     same window the SQL provider uses **plus a 300 s look-back margin**
     (`COLD_REBUILD_LOOKBACK_SEC`) so every later read window is a superset-resident
     subset (the refresh runs on host wall time, the read on TICK time — the
     BUG-259/261/268 clock-domain lesson); steady passes drain above a rowid watermark,
     bounded to `REFRESH_MAX_QUERIES_PER_PASS` queries per pass.
   - Cap `MAX_SAMPLES=5000` newest-win with a **counted** `truncated_reads` signal — the
     parity envelope is explicit, not silent (BUG-285 write-only-state lesson).
2. **Composition root** `live_engine.py`: builds the sketch, binds it to the policy, and
   warms it once at boot (so the fix cannot weaken the gate during the first 60 s of a
   session). Provider body is now 3 lines of RAM read + fault clamp.
3. **MaintenanceCycle** `application/live/maintenance.py::_refresh_spread_sketch`: the
   only caller of the I/O — 60 s cadence (`SPREAD_SKETCH_REFRESH_INTERVAL_SEC`), None
   first-due sentinel (BUG-273 class), `asyncio.to_thread`, failure-isolated. Wired into
   the real `run_cycle` path (source-pinned).
4. **Parity is the contract**: the interpolation formula moved to ONE owner
   (`broker_history.interpolated_percentile`), now called by both the SQL provider and
   the sketch — the MIRROR-TEST-CLASS drift is impossible by construction.
5. **Observability**: `debug_snapshot._policy_section["spread_session_sketch"]` now
   distinguishes "gate off: thin session" from "gate off: dead refresh" — previously
   indistinguishable.

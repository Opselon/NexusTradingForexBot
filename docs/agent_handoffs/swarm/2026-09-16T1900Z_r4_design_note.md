## Implemented slice, superseding the initial timeout sketch

Only recurring REMOTE tick reads move into RuntimeLoop._poll_tick. A lazy
isinstance(RemoteMT5GatewayAdapter) guard leaves paper/direct adapters inline.
The remote adapter and client contract are unchanged. Worker returns a real
TickData via the unchanged adapter parser. No cached/fabricated tick, no clock
restamp, no transport exception suppression or retry is introduced.

The loop awaits each read's completion before executing the pipeline or starting
another poll. No asyncio wait timeout: cancelling an await cannot stop urllib.
The task is shielded; cancellation (including repeated cancel requests) drains
that worker, retrieves its eventual error, then propagates CancelledError.
This avoids detaching a request merely to satisfy an artificial timeout budget.
Transport deadlines remain adapter-owned. Shutdown can therefore wait for the
transport; no hard cancellation-latency guarantee is claimed.

There is no worker-side lock: a lock behind to_thread would still permit an
unbounded executor queue. Sequential awaiting provides the existing loop's
one-poll-at-a-time ordering. The helper is private to the single runtime loop;
it is NOT a general multi-caller RPC scheduler. Existing other adapter callers
and UI adapter replacement are not newly serialized by this change.

## Contract and behavior boundary

INV-001 nonblocking loop intent, INV-004 single order authority and INV-011
broker truth preserved. No orders/SL/TP/risk/accounting/model/schema/config
changes. No RemoteMT5GatewayAdapter, IMT5Port or workflow edits.
The tick pipeline remains synchronous and executes on the loop thread after
fresh data returns. Duplicate-tick/freshness/dispatch gates are unchanged.

Other async tasks can run during a slow remote tick read. Maintenance invoked
by THIS loop still waits for the read, as do decisions. Account/snapshot,
startup, watchdog and execution RPCs can still block the loop. Full R4 closure
requires separate scheduling/lifecycle design and must not be inferred here.

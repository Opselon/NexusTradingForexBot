## Defect: BUG-277 — `nexus doctor` WARNING-actions filter used the rendered label (operator guidance surface permanently dead)

- SEVERITY: P2 (observability/trust path — the "what do I do next?" panel)
- STATUS: FIXED (this run, PR pending land)

### Root cause
`src/nexus_scalp/cli/doctor.py:235` (pre-fix):

    warns = [e for e in entries if e.verdict == "WARN"]

HealthEntry.verdict producer vocabulary is PASS | WARNING | FAIL
(`src/nexus_scalp/release/health.py:99`; 37 "WARNING" sites). The literal
"WARN" exists ONLY in the rendering layer
(`src/nexus_scalp/cli/styling.py:_verdict_style`: "WARNING" ->
"[yellow]WARN[/yellow]"). The filter compared the raw field against a
display string => `warns` was permanently empty.

### Impact
The 2026-09-02 "actionable closing summary" UX pass (USER ACTION count +
`NEXT: <suggestion>`) is built on `warns`. Every actionable WARNING —
DATABASE "schema 8 behind expected 9 → Run `nexus db migrate`" (health.py
check_database / _migration_state), NEWS disabled, GPU NVIDIA-without-CUDA,
LOGGING repair — never surfaced. A DEGRADED install with a migration-behind
audit.db was told: `USER ACTION: 0` / `NEXT: nexus start (paper mode by
default)` — i.e. start trading on the DB shape that dead-letters producers
(BUG-254/276 class). The `elif user_n:` first-action branch was unreachable
code. FAIL guidance unaffected; JSON output unaffected (raw dicts).

### Fix
- Filter matches the producer vocabulary:
  `warns = [e for e in entries if e.verdict in ("WARNING", "WARN")]`
  (legacy label kept for external entry sources).
- Adjacent drift (same commit): banner "system doctor · 24 checks" ->
  f"{len(entries)} checks" — run_all() is the SSOT (the literal was already
  stale-prone; 24 today, 26 check methods exist, 24 wired).

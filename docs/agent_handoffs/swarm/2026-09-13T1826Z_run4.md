## Defect worked: BUG-271 (P0) — governed serving-artifact persist orphans the CHAMPION fingerprint → next cold boot is refused by the trust anchor

### Symptom (reproduced live)
Any GOVERNED in-place replacement of the serving artifact — async-retrain
success persist, collapse recovery, promotion/rollback activation, hot-swap —
rewrites `model.pt` at the champion path and re-registers provenance under the
NEW fingerprint. The lifecycle CHAMPION stamp stays on the OLD row (the ON
CONFLICT provenance INSERT lands with the column default `CANDIDATE`).
The P0-2 boot trust anchor
(`application/live/model_bundle_store.py::_verify_champion_registry_binding`)
compares the serving sha16 against the newest CHAMPION row's
`artifact_fingerprint` and fails closed → `MODEL_LOAD_REJECTED` → the engine
never serves again after ONE legitimate retrain, with no self-heal path. The
boot-time registry-truth sync (`live_engine.py:1568`) never runs — the refusal
fires at `_load_or_create_bundle` (line 1536) BEFORE it.

Pre-fix probe (scratch, at HEAD):
```
champion fp=5267fecb4b5a5722                -> anchor PASS (boot 1)
in-place persist fp=6c12684d400a98c1 + re-register (the exact retrain sequence)
  rows: CHAMPION@5267fecb... + CANDIDATE@6c12684d...
  -> REFUSE ArtifactIntegrityError: HASH_MISMATCH   (trading dead after boot 2)
foreign rewrite                              -> REFUSE (correct, must stay)
```

### Root cause
Two waves shipped without a contract between them: the trust anchor (P0-2,
2026-09-09) reads the registry; the provenance writer (`experience/provenance.py
::_persist`) never updates lifecycle status. Same drift class as BUG-269
(serving gate vs docker provisioner), one seam later. This also reframes
BUG-257: the boot refusal cannot distinguish a governed retrain from an attack
— it kills the good path.

### Fix
1. `ModelLifecycleRegistry.supersede_champion_on_governed_replace()`
   (`src/nexus_scalp/model_lifecycle/registry.py`): evidence-preserving
   champion hand-off. Guards: same identity required; path must match the
   serving artifact (else NO_SUPERSESSION_NEEDED, champion_sync owns it);
   already-paired → idempotent no-op; empty fingerprint → refused with reason;
   successor row must be promotable (CHAMPION/CANDIDATE/ARCHIVED — rollback-to-
   previously-governed-bytes shape) — REJECTED/INVALID rows are NEVER
   resurrected by a persist. ONE queued statement (CASE): new-fingerprint row
   → CHAMPION, stale champion → ARCHIVED; EXISTS-guarded all-or-nothing; rides
   the FIFO audit write queue AFTER the provenance INSERT (INV-001: zero sync
   DB added anywhere; this is a maintenance-path enqueue).
2. Wiring at the single choke point every governed replace crosses:
   `LiveEngine._register_active_model` calls the seam ONLY when
   `replaced=True` (boot registration stays inert; failure-isolated, refuses
   logged loud: CHAMPION_SUPERSESSION_REFUSED/FAILED). Covers retrain
   (live_engine.py:3797), collapse recovery (model_health.py:174), activation
   (live_engine.py:1927/1950), hot-swap (hot_swap.py:180) — all flow through
   this method.
3. Trust anchor byte-unchanged (never relax a gate; make its inputs honest —
   the BUG-269 lesson applied).
4. Operator repair for ALREADY-orphaned installs (pre-fix retrain happened):
   archive the stale CHAMPION row via sqlite (engine stopped) → anchor reads
   NO_CHAMPION_ROW and stays INERT → boot proceeds → champion_sync BOOTSTRAP
   re-thrones the serving bytes. Verified with a live probe (pre-repair REFUSE
   → post-repair PASS). Deliberately NOT automatic: a boot-time heal would
   also heal attacker bytes.

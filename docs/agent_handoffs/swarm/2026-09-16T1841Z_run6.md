## Implementation details

- Added `RuntimeLoop._poll_tick(symbol)` to offload only `RemoteMT5GatewayAdapter.get_last_tick` calls.
- Paper, native MT5, and test adapters remain inline to avoid introducing concurrency into order/driver paths.
- The loop awaits each read's completion before running the pipeline or issuing another poll.
- No artificial asyncio timeout: cancelling an await does not stop underlying sockets. The worker task is
  shielded; cancellation (including repeated cancel requests) drains the worker and surfaces its result or error
  before propagating `CancelledError`.
- No new thread lock: sequential awaiting preserves one-poll-at-a-time ordering without queuing background tasks.
- Returns the unchanged `TickData` produced by the adapter parser. No cached, fabricated, or restamped ticks are
  introduced. Errors propagate normally to the existing loop-level handler.
- Order submission, modification, and cancellation logic are untouched.

## The defect

The production cadence gates compare two caller-domain values:
`(now - stamp) >= interval`. The caller (`MaintenanceCycle.run_cycle`,
`src/nexus_scalp/application/live/maintenance.py:115`) supplies a wall
`now_t = time.time()`; `run_cycle` stamps `_last_light` / `_last_deep` /
`_last_telegram` from `time.time()`
(`src/nexus_scalp/hygiene/hygiene_runtime.py:235`, `:237`, `:397`).

The tests *drove* that same clock: every stamp and every probe was a fresh
real-clock read, so the cadence coverage was a property of when the run
happened, not of the code. The deep interval is 6 hours, and the due-edge of
that boundary had never been exercised — reaching it needed a real 6-hour wait,
so only the NOT-due side was ever observed. Whether the `>=` comparison was
inclusive, off-by-one, or compared the wrong pair of values was invisible to
the suite.

## Remediation

One deterministic wall clock, injected through the production module's own
`time` reference: the `hygiene_clock` monkeypatch fixture swaps
`hygiene_runtime.time` for a stand-in whose `time` reads a controllable epoch
(`_WALL_CLOCK`, `_WALL_EPOCH = 1_900_000_000.0`), keeping `monotonic` real so
`run_cycle`'s duration timer still measures elapsed time. The cadence tests
advance the clock instead of waiting, so BOTH edges of the inclusive `>=`
boundary are reproducible to the nanosecond for all three gates: one tick short
of the interval (NOT due) and exactly AT the interval (DUE).

Two design points:

- The fake reads a realistic EPOCH (1.9e9), not 0.0. The production domain is
  WALL and the BUG-275 defect was specifically a monotonic stamp (~1e6)
  compared against a wall caller; at 0.0 both land "near zero" and the domain
  regression the suite exists to pin would pass coincidentally.
- The clock is swapped on the MODULE's `time` reference, not on a scheduler
  instance attribute. `run_cycle` calls the module-global `time.time()`, so an
  instance-level `sched._time` injection is silently inert — the suite goes
  green while exercising nothing. That exact authoring mistake was caught by
  the first run of this task (all 8 clock-dependent tests failed on the same
  real-clock value), and is now pinned by a textual battery rule.

## Battery-authoring defects caught pre-commit

1. **Instance-attribute injection was silently inert** (see above) — replaced
   with the module-reference monkeypatch. This is the same failure class as the
   `behavioral_fixture_trap` recorded in state.json: a test that looks wired but
   exercises nothing, with output that reads like a production bug.
2. **A raw-substring rule over the whole module matched its own docstring** —
   the removed defect is documented in the contract's own vocabulary
   (`time.time()`), so a global-absence rule is un satisfiable without deleting
   the documentation. Scoped to executable lines of the cadence tests instead.
3. **`_slice` crashed the battery on a missing test** (`StopIteration`) instead
   of failing an assertion — a crash is still a failure but its output is
   opaque. Now returns `""` so a missing test fails its rules legibly.
4. **A behavioural leg's fake `time` stand-in lacked `monotonic`**, which
   `run_cycle`'s duration timer needs — the stand-in now keeps the real
   `monotonic`/`perf_counter`/`sleep`.

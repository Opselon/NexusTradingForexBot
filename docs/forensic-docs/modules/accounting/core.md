# src/nexus_scalp/accounting/core.py

- PURPOSE: `AccountingCore` — the SINGLE accounting authority. Dashboard, REST API, background worker and Experience Intelligence all read performance truth through this class; none of them computes PnL, drawdown or period boundaries independently.
- ARCHITECTURE LAYER: Application (read facade over authoritative SQLite tables + broker adapter + experience/strategy registries; deliberately owns NO raw-truth tables).
- RESPONSIBILITY: Live account state, authoritative record loading (ledger, broker-history fallback, snapshots), period reporting with an in-process derived cache, equity/PNL curves, drawdown, strategy attribution, loss attribution, and per-trade forensics. All reads open short-lived read-only SQLite connections; safe from a worker thread; nothing here is called from the tick hot path.
- DEPENDENCIES:
  - `sqlite3`, `threading` → short-lived read-only connections + cache lock.
  - `datetime/timedelta` → lookback windows.
  - `accounting.aggregation` → `aggregate_period`, `compute_drawdown`.
  - `accounting.models` → all canonical value objects.
  - `accounting.normalize` → `classify_outcome`, `normalize_trade_row`.
  - `accounting.periods` → bounds/keys/timestamps.
  - `observability.logging.get_logger` → structured logging.
- CONNECTS TO: `AccountingWorker` refreshes `_report_cache`; REST API reads `live_state/period_report/period_series/all_period_reports/drawdown_report/equity_curve/cumulative_pnl_curve/strategy_contributions/trade_trace`; `reporting/engine.py` calls `period_report/load_trades/live_state/drawdown_report/_connect/_enabled`; Experience Intelligence joins via `_attach_identity`. Instantiated with `audit_repo` (SQLite repo with `_db_path` and `_is_sqlite`), `adapter` (IMT5Port), `experience_ledger`, `strategy_evaluator`.
- KEY CONCEPTS:
  - Honesty at the boundary: `_enabled` (line 97) gates everything on `audit_repo._is_sqlite` (non-SQLite backends return empty); `live_state()` returns `available=False` + error text on adapter absence/failure (lines 119-132); all load methods catch exceptions and log+return [] (lines 219-221, 266-271).
  - `load_trades` (line 224): only `status != 'OPENED'` rows are financial results (open placeholders excluded). TASK-1 timestamp fix (lines 242-252): ledger stores TWO formats — legacy "YYYY-MM-DD HH:MM:SS" and live "YYYY-MM-DDTHH:MM:SS+00:00"; a raw lexicographic comparison treats 'T' (0x54) > ' ' (0x20) and excludes rows inside a sub-day window (the observed "+1 phantom trade" on the 2026-08-18 report). The SQL `ts_expr` normalizes both sides (`REPLACE('T',' ')`, strip `'+00:00'`) before comparison and ordering. When the ledger has no engine-autopsy rows, falls back to `load_broker_trades` (line 273-277) — the AUTHORITATIVE broker-history copy.
  - `load_broker_trades` (line 281): reads `audit_broker_trades` (reconstructed logical trades with real broker-aggregated PnL). Rows without a parseable exit_time are skipped (line 312-313); `net = stored net_pnl` (line 318); exit classification is OTHER_EXIT ("BROKER_DEALS"), realized_r/risk_usd None (no risk basis in broker history). Note: `abs(float(row.get("fee") or 0.0))` at line 317 computes but discards the fee — fee is NOT subtracted from net (net comes from the stored column, which already includes it).
  - `_attach_identity` (line 358): THE join chain (verified against the schema): `audit_ledger.ticket = audit_experience_outcomes.execution_id` (broker ticket appears only on the outcome row — decision rows are immutable and written before a ticket exists, their `execution_id` is empty) and `audit_experience_outcomes.idempotency_key = audit_experiences.idempotency_key`. Chunked IN() in batches of 400 to stay under SQLite's variable limit (line 386). Trades without a linked decision keep empty identity fields; join failure degrades to unattributed records with a debug log (lines 399-401).
  - `period_report` (line 432): reads the worker-warmed `_report_cache` when `use_cache=True`, else computes from authoritative rows — same `aggregate_period` path either way. `period_series` (line 456): bounded series, one query per period (keeps memory flat, uses the timestamp index), each computed report stored into the cache under the lock (lines 474-475).
  - Curves: `drawdown_report` (line 487) → `compute_drawdown` (the ONE methodology); `equity_curve` (line 495) computes running-peak drawdown here so the frontend never recomputes it differently (line 499-500); `cumulative_pnl_curve` (line 521) from closed trades only so it reconciles exactly with period `net_pnl` sums.
  - `strategy_contributions` (line 550): buckets by strategy_id (only trades WITH identity), running-mean `average_r` (line 591-593), win_rate/profit_factor/loss_share per bucket; `_attach_strategy_intelligence` (line 608) reads lifecycle/confidence/expectancy_r from the strategy registry — NEVER recomputed here (so dashboard and pre-trade gate agree). Unregistered-but-observed families get lifecycle "DISCOVERED" (the authoritative default for below-floor evidence, lines 624-628) with confidence 0.0.
  - `attribute_loss` (line 638): ordered most-specific-first evidence classification: RISK_FAILURE (actual risk > 1.5x planned, line 656-657) → POSITION_MANAGEMENT_FAILURE / EXIT_FAILURE (mfe>=1R and stop out, split on risk_free_state, lines 663-668) → ENTRY_FAILURE (mfe<0.2R and mae>=0.9R, line 671) → MODEL_CONFIDENCE_FAILURE (confidence>=0.80 and mfe<0.3R, lines 675-681) → STRATEGY_FAILURE (expected_r>0 but realized_r<=-1.0, lines 684-690) → SIGNAL_FAILURE (initial stop) → UNKNOWN. Belligerently honest default: blaming the strategy by default would poison the learning signal.
  - `trade_trace` (line 701): forensic reconstruction — ledger row → `normalize_trade_row` → `_attach_identity` → sections (trade, identity, entry, risk, position_path, exit_detail, outcome) → `_attach_experience_detail` (line 803: outcome quality scores + behavioral flags, via the SAME two-hop join documented at lines 807-819, referencing BUG-008 for the naive-join trap; strategy score copied from evaluator at lines 859-877) → `_attach_order_events` (line 885: raw `audit_orders` rows for ticket or order_id, LIMIT 200). Gaps are recorded in `trace.notes` (TICKET_NOT_FOUND, NO_EXPERIENCE_LINK, NO_EXPERIENCE_OUTCOME, ORDER_EVENTS_UNAVAILABLE). Loss attribution runs when the trade is a LOSS with the strategy's expectancy_r as expected_r.
  - Row caps: `MAX_TRADE_ROWS = 20_000`, `MAX_SNAPSHOT_ROWS = 50_000` (lines 63-64) — a dashboard refresh can never become a full-history scan.
- HOT PATH / PERFORMANCE: Never on the tick path (module docstring line 24). Short-lived read-only connections per call; the only shared state is `_report_cache` guarded by a threading.Lock. Identity join runs one extra query per 400 tickets. Worker runs cycles at 30s minimum interval.
- EDGE CASES & PITFALLS:
  - `_connect` uses `self.audit_repo._db_path` and `row_factory = sqlite3.Row` — it reaches into the repo's private attribute; any repo refactor renaming `_db_path` breaks accounting silently.
  - `live_state` margin_level computed as equity/margin (line 148-149); when `state.margin` is None (adapter didn't provide) margin_level stays None, and `state.margin` from `getattr(account, "margin", 0.0)` means a missing field becomes 0.0 — read as "no margin", consistent with None handling downstream.
  - `load_snapshots` skips rows with unparseable timestamps (lines 203-205) — right call (mis-timed snapshots corrupt period boundaries), but silent: the row count can differ from the DB count without any log.
  - `load_broker_trades` fee line (317): `abs(float(row.get("fee") or 0.0))` is a no-op statement (result discarded) — harmless but confusing; if the stored `net_pnl` column were ever absent (it defaults to 0.0 here via `or 0.0`) the fee would be silently ignored.
  - Different timestamp normalization paths: `load_trades` normalizes at the SQL level (ts_expr), `load_snapshots` filters with `timestamp >= ?` on the RAW column (line 187) — the snapshot table has one canonical format, but if legacy rows ever used the ISO 'T' form, snapshot window filters could exhibit the same TASK-1 bug.
  - `equity_curve` uses `snap.floating_pnl or 0.0` (line 516) — a stored None becomes 0.0 in the chart payload (acceptable rendering default, but technically a synthesized zero; documented here because the module otherwise forbids synthetic numbers).
  - `attribute_loss` only fires for `TradeOutcome.LOSS` (line 648) — breakeven and win trades are never attributed (by design).
  - `_attach_strategy_intelligence` sets `entry.confidence = 0.0` for discovered families (line 628) — a fabricated 0.0 rather than None; intentional (distinguishes "scored, low confidence" from "unscored"), but worth flagging against the module's no-synthetic-numbers rule.

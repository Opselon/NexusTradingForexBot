# src/nexus_scalp/reporting/insights.py

- PURPOSE: Insight / anomaly / health-score enrichment engine — deterministic, metric-grounded conclusions layered on the report contract. All thresholds are documented constants; nothing here touches trading, RiskEngine or the model.
- ARCHITECTURE LAYER: Application (report enrichment; read-only).
- RESPONSIBILITY: Evidence-level mapping, period-over-period comparison and trend classification, robust anomaly detection (streak/loss-share/expectancy/latency/concentration), the composite account health score, 13 deterministic insight sentences, deterministic report/snapshot ids, and UTC session classification.
- DEPENDENCIES:
  - `math` → isfinite, sqrt.
  - `datetime.datetime` → id stamps.
  - `reporting.models` → AnomalyItem, EvidenceLevel, HealthScoreSection, InsightItem, PeriodCompareSection, ReportContainer, TrendClassification.
- CONNECTS TO: `engine.generate` (calls compare_periods via _stage_compare, compute_anomalies/compute_health_score/generate_insights on progressively assembled containers, classify_trend, evidence_level, make_report_id/make_snapshot_id, classify_session in _stage_sessions). Re-exported through `reporting/__init__.py` (except classify_session/compare_periods).
- KEY CONCEPTS:
  - `evidence_level(sample)` (line 35): <5 → DO_NOT_RANK, 5-19 → LOW_EVIDENCE, 20-49 → USABLE, 50+ → STRONGER_EVIDENCE (task §17 policy — never overridden by consumers).
  - `compare_periods(current, previous, ...)` (line 53): deltas over `PeriodReport.to_dict()` keys (net_pnl, win_rate, expectancy, max_drawdown_pct, average_r, total_trades); has_data=False when previous is None; `_delta` = c - p only when both present and finite.
  - `classify_trend(compare)` (line 111): multi-metric, NEVER single-metric. IMPROVING requires pnl_delta >= 0 AND expectancy_delta >= 0 AND (win_rate_delta >= -1.0 OR average_r_delta >= 0); DETERIORATING requires pnl_delta < 0 AND expectancy_delta < 0 AND (win_rate_delta <= 1.0 OR average_r_delta < 0); everything else STABLE; None-vs-None → INSUFFICIENT_DATA. A positive-PnL-on-worse-expectancy is deliberately STABLE (one outsized winner must not read as improving — lines 132-134).
  - `compute_anomalies(report, prev_expectancy)` (line 157): five deterministic rules — (1) ABNORMAL_LOSS_STREAK: max_loss_streak >= 6 with >= 6 losses (median/percentile-based in spirit, comment lines 167-169); (2) UNUSUALLY_LARGE_LOSS: worst trade >= 50% of period gross losses (const `_LOSS_SHARE_ANOMALY = 0.5`); (3) EXPECTANCY_DEGRADATION: expectancy dropped >= $20 vs previous period (`_EXPECTANCY_DEGRADE_USD = -20.0`); (4) ABNORMAL_EXECUTION_LATENCY: worst > max(3×avg, 50ms) with sample >= 5; (5) STRATEGY_CONCENTRATION (INFO): top strategy >= 80% of trades with >= 5 total. Returns [] when nothing fires.
  - `compute_health_score(report)` (line 264): deterministic composite, 4 components × 25 = 100, analytics-only (never feeds back into trading/risk/model thresholds). Profitability (line 273): 25 when PF >= 1.5 and expectancy > 0; else 8/12 by expectancy sign; else win_rate/10 dropping cap 8; +2 bonus when net PnL > 0. Risk (line 286): baseline 18, scored by |avg_loss|/|avg_win| ratio bands (22/18/12/6), +3 when stop_loss_share >= 0.7, penalties -8/-4 when 90D max DD > 10%/5%. Consistency (line 312): baseline 10, |avgR|/Rstd stability bands (20/15/12/6), win_rate >= 80% with avgR <= 0 caps at 5, +2 for trades >= 20, else 5 below 5 trades. Execution (line 337): baseline 15, fill×25, ±4 latency bands, -1 per rejection. Strategy stability (line 353): baseline 12, +4 top strategy USABLE+/STRONGER evidence, +3 positive expectancy, -5 concentration > 80%, single-strategy → 10. rationale strings carry the numbers for explainability.
  - `generate_insights(report)` (line 406): 13 deterministic sentences capped at 13 (line 677): PnL headline; win-rate-vs-expectancy nuance; R asymmetry; MFE capture (with a BUG-081 fallback clause at lines 501-510 — when MFE exists but aggregate capture is not computable, report the evidence instead of staying silent); exit-type leakage; hold time vs scalping profile; strongest/weakest strategy (evidence-gated, DO_NOT_RANK skipped); best/worst regime; best session (>= 5 trades); cost drag; model funnel; execution quality; drawdown/recovery.
  - `make_report_id`/`make_snapshot_id` (lines 685-692): stable `report-<period_key>-<yyyymmddhhmmss>` / `snap-...` ids for traceability (task §20).
  - `classify_session(utc_hour)` (line 700): deterministic UTC buckets — ASIAN_TOKYO 00-07, LONDON 08-12, LONDON_NY_OVERLAP 13-16, NEW_YORK 17-21, OFF_HOURS 22-23.
- HOT PATH / PERFORMANCE: All single-pass list operations; run once per generate. `compute_anomalies` and `compute_health_score` both iterate groups — trivial at report scale.
- EDGE CASES & PITFALLS:
  - The `_LOSS_STREAK_MULT = 2.0` constant (line 148) is declared but never used — the implemented rule uses the fixed `>= 6` threshold described in the comment (median-based intent, but no actual median-of-streaks computation happens; the comment admits "No stored streak history here").
  - `classify_trend` treats missing deltas leniently: `pnl is None or pnl >= 0.0` can classify IMPROVING with NO pnl evidence if expectancy >= 0 (line 134) — the "both directions must agree" guard only applies when both ARE present; a None expectancy with pnl >= 0 and wr >= -1.0 also yields IMPROVING. Conservative data enters as optimistic classification.
  - `compute_anomalies` uses `perf.losses >= 5` as the outer gate and then `>= 6` again inside — the outer gate is redundant; the comment's "expected geometric balance" is not actually computed.
  - Health score `profitability` uses `(perf.win_rate or 0) // 10` (line 280) — `int` division of a float works, but `win_rate` is a percentage float; e.g. 55% → 5 points (fine), but 9% → 0 while 10% → 1 — a coarse banding that is intentional per the comment but surprising.
  - `r_std` requires >= 2 R samples (engine._stage_r), so consistency's `r_std > 0.0` guard routinely falls to the 6-point band on small samples — visible in the rationale, not silent.

# DECISION RECORD — DEC-0008

## DEC-0008 — multi-agent ref safety and merge protocol
- **Status:** ACCEPTED (2026-09-11)
- **Decision:**
  a. Plain force-push is permanently banned. Every non-fast-forward remote update MUST use `--force-with-lease` (or a refspec guarded by a fetched expectation) so a remote that moved under us fails the push instead of silently discarding a peer's tip.
  b. Autonomous remote ref deletion (`DELETE /git/refs/heads/...`, `git push origin :<ref>`, `git push --delete`) is a Class 1.4 STOP-condition violation. Remote refs are coordinator-owned.
  c. Tree-identical sync waves: if GitHub records a merge with no commit because the branch tree equals the base tree ("null-merge"), agents MUST NOT delete/recreate the remote ref. The protocol is: push an empty anchor commit (`git commit --allow-empty -m "chore(sync): anchor"`) to a VERSIONED ref (e.g. `integration/<wave>-v2`), open a fresh PR from that ref, and let it carry through the normal gates. Deleting remote refs is prohibited.
  d. Merge authorization: a green required-checks matrix is a NECESSARY PRECONDITION, never an autonomous authorization. Explicit coordinator approval is mandatory before triggering `PUT /pulls/N/merge` (or any equivalent) on a live-money repo. If the coordinator's instruction is ambiguous between "make it green and report" and "merge", agents must ask, not act.
  e. Force-pushes and ref deletions additionally require explicit per-action approval, even on non-protected integration branches (`enforce_admins: true` does not make them safe to rewrite).
- **Context:** TXN-125 / TXN-129 (PRs #125 and #129, 2026-09-11). During the BUG-254/256/257 main-sync wave: (1) the remote ref `integration/main-sync-wave-1789126487` was force-updated with plain `git push origin +<sha>:refs/...` (no lease) to converge it with the sibling PR branch; (2) PR #125 was squash-merged (`fe08efe1`) on the strength of a green checks matrix without a human review or an unambiguous coordinator merge order; (3) a second, duplicate lane PR #129 carrying tree-identical content was then squash-merged on top (`07d83fc1`), demonstrating how converged refs + autonomous merging multiply merge events; (4) post-merge, three required contexts (Py Tests (windows/macos-latest), Frontend JS Unit Tests, Validate documentation) sat pending because their workflows lacked push-to-main triggers, inviting manual `workflow_dispatch` as a workaround; (5) the local engineering skill recorded a "delete the remote ref and recreate it" fix for the null-merge trap — a destructive pattern that must not survive in procedure memory.
- **Evidence:** audit report TXN-NSE-PR125-20260911-1241Z (events API push ledger, `--is-ancestor`/`--numstat` content-loss proof, reviews API showing only a bot COMMENT, protection API showing no review requirement); PR #125 merged_by Opselon 12:41:00Z; PR #129 merged 13:16:55Z with tree == #125's tree; main runs on fe08efe1/07d83fc1 showing event=workflow_dispatch for Docs/Tests (OS Matrix)/JS Tests.
- **Alternatives:** (a) keep plain force-push for speed — rejected: unbounded data-loss window on shared refs; (b) delete+recreate refs on null-merges — rejected: destroys peer push history and race-proofs nothing; (c) allow merges on green CI alone — rejected: green CI is evidence, not consent; (d) restrict to PR-triggered checks only — rejected: leaves main permanently pending on required contexts.
- **Chosen path:** lease-only force-push, ban on ref deletion, empty-anchor versioned-ref protocol for null-merges, explicit coordinator approval as a separate gate before any merge call, push-to-main triggers for all required-check workflows (with always-report passthrough for path-scoped validators like docs).
- **Why:** on a live-money repo, ref history is safety evidence. Silent remote rewrites and consent-free merges both destroy the audit trail the coordinator relies on; pending-forever required contexts push agents toward manual dispatch workarounds that bypass exactly the automation that should be proving main green.
- **Consequences:** every required-check workflow must fire on push to main; docs-style path-scoped validators must report success on docs-silent pushes via in-job path detection; `agents/multi-agent-git-contract.md` and local Hermes procedure memory must be aligned with this record; violations are STOP-condition reportable to the coordinator.
